Part 1 - Cypher Basics


In this tutorial you will learn the basic concepts of Cypher, Neo4j’s query language. Cypher is a graph query language that is used to query the Neo4j Database. Just like you use SQL to query a relational database, you would use Cypher to query the Neo4j Database.

In this tutorial learned to:

  1. 1. Insert data into the graph.

  2. 2. Update and delete data.

  3. 3. Run basic queries on this database.

Creating nodes with the CREATE clause


Nodes and Relationships are the basic building blocks of a graph database. A node in graph database is similar to a row in a relational database. Two nodes can be connected with a relationship. The database is still empty, so let’s start by creating a few nodes using the CREATE clause.

In writing a Cypher query, a node is enclosed between a parenthesis — like (:Person) where Person is the type of node it is referring to.

CREATE (:Person {name: "John Doe" })
CREATE (:City {name: "Utrecht"})
Hint: You can click on the query above to populate it in the editor.

 

When creating nodes you can set properties directly by adding them between curly brackets {property_name: "property_value"}. Note that the property names are not specified with quotes ("), the values do contain quotes if the value is a string.

Querying the graph with MATCH


We can now query the database to retrieve nodes. We added a variable p before :Person and use it to return the node.

MATCH (p:Person) RETURN p

Running CREATE twice results in duplicate data


Important to note is that the CREATE clause does not check if the data is already in the database. If you’d run the create clause again you will end up with duplicate data.

Normally you would like to prevent that, but for the sake of learning let’s allow some duplicates.

CREATE (:Person {name: "John Doe" })
CREATE (:City {name: "Utrecht"})
Hint: You can also use `:history` to see your previous queries

Empty the database with DELETE


Let’s start over with an empty graph and run the following query:

MATCH (n:Person|City) DELETE n

This query deletes nodes of type Person or City.

You can only delete nodes that have no relationships, to delete nodes and any relationships connected them, use the DETACH DELETE clause.

Tip: Double check that the query covers what you intend, also check if you are on the correct database!

Creating nodes with the MERGE clause


You can use the MERGE clause instead of CREATE.

MERGE (:Person {name: "John Doe" })
MERGE (:City {name: "Utrecht"})

MERGE is slower than CREATE if you have a lot of data, but the advantage is that it checks if what you try to add is already present in the database, preventing duplicates.

Adding Relationships using MATCH and MERGE


Two nodes can be connected with a relationship. In writing a Cypher query, relationships are enclosed in square brackets - like [:LIVES_IN].

MATCH (p:Person)
WHERE p.name = "John Doe"
MATCH (c:City)
WHERE c.name = "Utrecht"
MERGE (p)-[:LIVES_IN]->(c)

Here we first use MATCH to find the nodes involved in the relationship and then create the relationship with the MERGE clause.

Cypher provides a visual way of matching patterns and relationships. It relies on the following ascii-art type of syntax: (nodes)-[:CONNECT_TO]→(otherNodes). Rounded brackets are used for nodes (), and -[ ]→ and ←[ ]- for relationships. Relationships have a direction in Neo4j indicated by the arrow.

Querying patterns using MATCH


Now we have created both nodes and relations in the graph, we can retrieve patterns from the graph.

MATCH p=(:Person)-[:LIVES_IN]->()
RETURN p

Here we match a certain pattern, assign it to a variable and return it.

Updating properties with SET


If you like to add or update an property to an existing node you can use MATCH to select the nodes you want to update and then use SET to update or add an property.

MATCH (c:City) WHERE c.name = "Arnhem"
SET c.province = "Gelderland"
RETURN c

Recap


Ok, so far we have learned the following:

  1. 1. Add nodes into the graph with CREATE or MERGE

  2. 2. Add relations into the graph with MATCH and MERGE

  3. 3. Retrieve nodes and relations with MATCH

  4. 4. Delete everying from the graph records with DETACH DELETE

  5. 5. Update nodes with new properties using SET

Now, let’s use these new skills to create a graph together.

Create a personal graph


You can change the following template to create your personal graph. Feel free to add other type of labels, you might need new variable names when you do. If you are stuck feel free to ask one of our colleagues to help you out.

When the query runs successfully, you can share it in the chat if you like. This way we can combine all personal queries and create a "participant graph".

// create nodes
MERGE (person:Person {name: "John Doe"})
MERGE (squad:Squad {name: "Squad xxx"})
MERGE (area:Area {name: "Area xxx"})
MERGE (tribe:Tribe {name: "Tribe xxx"})
MERGE (role:Role {name: "Data Scientist"})
MERGE (language:Language {name: "Python"})
MERGE (hobby1:Hobby {name: "Bouldering"})
MERGE (hobby2:Hobby {name: "Piano"})
MERGE (city:City {name: "Arnhem"})

// use the variables from the created nodes to create relations
MERGE (person)-[:WORKS_IN]->(squad)
MERGE (squad)-[:IN_AREA]->(area)
MERGE (area)-[:IN_TRIBE]->(tribe)
MERGE (person)-[:LIKES_LANGUAGE]->(language)
MERGE (person)-[:HAS_HOBBY]->(hobby1)
MERGE (person)-[:HAS_HOBBY]->(hobby2)
MERGE (person)-[:HAS_ROLE]->(role)
MERGE (person)-[:LIVES_IN]->(city);

You can view the results using the following query:

MATCH p=(person:Person)-[*..4]-()
WHERE person.name = "John Doe" RETURN p

It works best if we are a bit consistent in the naming. We can try to align the Tribe, Area names a bit using the chat as well.

Lets see how far we get with this experiment :)
